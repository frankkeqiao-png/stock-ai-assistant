# 推荐历史保存说明

## 保存原则

`trading-assistant-state` 分支保存运行时连续状态；`main` 分支只保存代码和配置。推荐历史采用追加式档案，不因日常刷新、候选池变化或页面展示限制而删除。

## 文件职责

| 文件 | 职责 | 保留规则 |
| --- | --- | --- |
| `trading-assistant-recommendation-archive.json` | 推荐历史的权威档案：首次推荐、每次推荐判断、每日价格轨迹、止损止盈与跟踪状态。 | 永久追加保存。 |
| `trading-assistant-recommendation-tracking.json` | 当前跟踪的工作快照，供刷新流程快速读取。 | 可滚动保留；不作为历史唯一副本。 |
| `trading-assistant.json` | 页面当前展示快照。 | 可重新生成；不作为历史唯一副本。 |

## 展示与容量

- 推荐日历从追加式档案生成，不再截取最近 30 或 90 个日期。
- 价格轨迹与推荐事件在档案中不做按天数截断。
- 用户确认剔除后，股票停止更新并在页面置灰，但历史仍保存。
- 如未来数据量明显增大，页面应采用按年份或日期筛选/分页；这只影响展示，不影响归档保留。

## 同步保护

同步脚本使用显式 Git 引用抓取 `trading-assistant-state` 分支，并在发布前将运行时文件强制加入该分支的索引。这样，GitHub Actions 的干净运行环境不会把已有云端状态误判为首次初始化，也不会用空白状态覆盖历史档案。

## 一次性恢复

`scripts/recover-recommendation-history.js` 会遍历状态分支中旧版推荐跟踪文件的历史提交，按股票代码、推荐事件和价格日期去重合并到追加式档案。该脚本可重复执行，不会重复写入同一条事件。
